# FLARE-LLM Large runtime

This app integrates the [official FLARE repository](https://github.com/jxzhanggg/FLARE), pinned to `7c8f76c788a01f9270a3badfd2eeab45a979c44a`, and its [released checkpoints](https://huggingface.co/Anony94/FLARE-checkpoints). The model is a dual face/lip visual encoder, projection adapter, and LoRA-finetuned Qwen2.5-7B decoder. It receives **no microphone audio**.

The [paper](https://arxiv.org/abs/2610.19559) reports 11.7% LRS2, 13.2% LRS3, and 34.3% WildVSR word error rates. These are benchmark results for the authors' evaluation, not measured accuracy for this app or a guarantee on webcam video. FLARE is an utterance model, not a native streaming model. The app repeatedly decodes the current retained utterance, then refines it once at a pause. Captions can change as more visual context arrives, and latency includes capture, face tracking and beam search.

## Install

Use **Python 3.10** for Fairseq's legacy dataclasses. Keep the lightweight API environment separate if desired. CUDA is required for the provided runtime. An estimated **28 GiB of free VRAM** is checked before loading; this is admission headroom, not a measured universal minimum. More memory may be needed for long clips or concurrent GPU workloads. The app never stops another GPU process.

```bash
uv venv --python 3.10 .venv-model
uv pip install --python .venv-model/bin/python 'pip==24.0' 'setuptools<70' wheel
.venv-model/bin/python -m pip install torch==2.9.1 torchvision==0.24.1 --index-url https://download.pytorch.org/whl/cu128 --extra-index-url https://pypi.org/simple
.venv-model/bin/python -m pip install -r requirements-model.txt -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu128
.venv-model/bin/python scripts/setup_model.py --download
.venv-model/bin/python scripts/setup_visual_speech.py
```

Both setup scripts are required. The second installs the visual speaking detector used by the browser app. Then follow the [README](README.md#get-started) to build and launch the interface. Install [uv](https://docs.astral.sh/uv/getting-started/installation/) first if it is unavailable.

CUDA 12.8 wheels support the local Blackwell GPU; choose another compatible PyTorch build on different hardware. The dependency selection is a compatibility port of the released Python 3.8 / PyTorch 1.13 training environment. End-to-end inference must be validated on an available GPU before claiming reproduced paper performance.

Downloads use about **25 GB** of model files, plus the Python/CUDA environment:

- FLARE Large finetuned visual checkpoint: 4.85 GB.

The setup script pins the FLARE checkpoint revision to `6187ad650dc1786a8efc8b6bfbee37bbf62c4b2e` and Qwen to `d149729398750b98c0af14eb82c78cfe92750796`, and records them in `models/revisions.json`. Source, weights, and virtual environments stay outside Git. Downloads use the published model hosts; webcam images are never sent to those hosts. Torch checkpoints use Python serialization and are loaded only from the explicit upstream release paths.

## Preprocessing and decoding

1. The API timestamp-resamples the actual capture to 25 fps; the model preprocessor also supports measured source fps for offline clips.
2. SFD detects the face and a 68-point face alignment network estimates landmarks. Multiple faces, prolonged tracking loss, tiny faces and very dark captures are rejected instead of producing guesses.
3. Short landmark gaps are interpolated, with at least 80% tracking coverage required.
4. Five stable nose/eye points are smoothed over 12 frames and aligned to AV-HuBERT's 256px mean face using a similarity transform. The lip ROI is 96 × 96 around landmarks 48–67.
5. The aligned full face is resized to 96 × 96. Both streams are converted to grayscale, center-cropped to 88×88, scaled to [0,1], then normalized with checkpoint mean/std (defaults .421/.165). No test-time random augmentation is used.
6. Both streams feed the released visual-only encoder and LoRA decoder, with its video transcription prompt, beam 30 and temperature 1.2. `FLARE_BEAM_SIZE=5` trades search breadth for speed; it should not be presented as the authors' evaluation setting.

**Known preprocessing limit:** the FLARE release describes LRS2/LRS3/VoxCeleb-style full-face crops but does not publish the original crop implementation. The aligned full-face crop here is an explicit deployment approximation. Lip alignment follows the [AV-HuBERT reference](https://github.com/facebookresearch/av_hubert/blob/main/avhubert/preparation/align_mouth.py). Detector differences, webcam framing, compression, short-window boundaries, and face cropping can all change word error rate. This app cannot honestly claim reproduced state-of-the-art performance until a held-out evaluation verifies it.

## Visual speech filter

`backend/visual_speech.py` loads the independently trained visual encoder and `lossV.FC` head from official [Light-ASD](https://github.com/Junhua-Liao/Light-ASD) commit `ed38c232de5efe0261dbd68627c0ade7cdfe14eb`. The TalkSet checkpoint and source SHA-256 are checked, and visual parameters load strictly. The encoder/head run in float32 inference mode. No audio fusion or GRU is involved; published audiovisual results do not establish this branch's webcam accuracy.

The classifier reuses SFD boxes returned by the existing landmark call, so no extra face detection is needed. It follows the upstream 13-frame median box smoothing, padded face crop, 224-pixel resize, grayscale center 112-pixel crop, and normalization (.4161/.1688). Scores are recomputed with the current temporal context, while boxes/landmarks remain cached. Fully byte-identical video frames supply zero activity instead of asking the classifier to infer speech from a frozen image. No lossy image-motion rule overrides the trained detector.

`backend/speech_gate.py` averages 25 contextualized scores and admits a clip if any newly evaluated mean reaches **0.4**. Crop smoothing and temporal convolutions each require six context frames, so 12 frames at each boundary are excluded. A session-local watermark on the exact 25 fps sampling grid consumes evidence once. The last 24 scores carry forward across windows; coalesced updates evaluate all newly available evidence, including speech between scheduled requests. Discontinuous or invalid evidence explicitly abstains. Quiet/uncertain decisions cannot open a new utterance. A confirmed pause may trigger one final decode of speech already detected; subsequent quiet updates retain the completed caption without running FLARE again.

The TalkSet checkpoint and threshold were frozen using the four first takes before inspecting second-take scores. With that fixed rule, all four second-take clips separated as intended: quiet stillness/head movement stayed suppressed and normal/subtle speech passed. Sequential, two-second coalesced, and three-second coalesced replay passed. The old filter admitted only 1/7 and 2/7 updates from the two subtle-speech recordings; the trained gate admitted 7/7 in each. Overlapping updates are correlated, and clip instructions are not precise frame labels. These are personal gate checks, not word-accuracy measurements.

**Start confirmation trial:** the original 0.4 rule now supplies continuation and pause evidence; opening a new utterance additionally requires three consecutive smoothed means of at least 0.8. The streak carries across continuous fresh evidence, resets below 0.8 or on invalid/gapped observations, and cannot be replayed by duplicate windows. The start candidate records the earlier 0.4 crossing, resetting after 800 ms of quiet. If stronger confirmation later arrives, `UtteranceReader` uses that original candidate plus the existing 1.6-second pre-roll. Unconfirmed candidates never authorize decoding or Stop refinement. Confirmed utterances retain the permissive continuation rule, including subtle sections below 0.8.

This change targets false starts that a single weak score could previously open. Both saved takes were consulted for the new thresholds, so neither remains held out for this trial. All four saved speech clips confirmed during their first scheduled update in offline replay; the four quiet clips did not confirm. Three adjacent smoothed means are correlated, and the scores are not calibrated correctness probabilities. This cannot establish a universal false-positive rate, prevent all confident detector mistakes, or fix arbitrary word errors during genuine speech. FLARE beam probabilities remain unused as silence confidence; no phrase blacklist or repetition penalty changes the model's predicted words.

Admitted FLARE face/lip tensors remain byte-identical to filter-off preprocessing, including a real recorded subtle-speech check with the installed SFD/FAN. FLARE normalization, BF16 weights, beam 30, and temperature 1.2 are unchanged. The utterance controller selects the retained recognition window as described below. The classifier adds a small inference step; it does not blacklist phrases or treat FLARE beam scores as silence probabilities.

The classifier's fully contextualized frontier lags the latest input by 480 ms. The browser collects another 640 ms after Stop when filtering is enabled, then finalizes normally. There is no true pre-start context: very short utterances at startup and abrupt camera loss remain limitations. No general promise of zero missed speech follows from these clips. The browser always enables this filter; only developer API calls can bypass it for controlled evaluation. Missing classifier assets fail loading explicitly rather than silently reverting to the old motion heuristic.

The previous modules (`activity.py`, `registered_activity.py`, `articulation.py`) remain for historical baseline evaluation with a preprocessor lacking a learned detector. They are not OR-ed into live decisions: their landmark fallback previously admitted sensor/tracker noise while stricter registration blocked subtle speech. `scripts/evaluate_speaking_examples.py` compares this baseline with both released visual checkpoints. `scripts/check_speaking_gate.py` verifies the frozen rule and can run loopback end-to-end checks without printing or saving recognized words. User clips and numeric reports remain in ignored local directories.

## Experimental visual evidence verification

`backend/grounding.py` implements a contrastive diagnostic inspired by [Visual Contrastive Decoding](https://arxiv.org/abs/2311.16922). That work studies image-language object hallucinations; it does not validate a lip-reading threshold. This implementation scores candidates already produced by the original beam search.

An isolated beam wrapper retains the actual winning token IDs (including EOS), scored alternatives and original visual/prompt embedding prefix. Teacher forcing scores those same IDs under the real prefix and three freshly encoded controls that repeat the first, middle or last prepared face/lip frame for the original duration. The prompt, token sequence, temperature 1.2 and prefix length remain equal. Content averages exclude EOS. The phrase-level trial withholds a proposal if all three real-minus-control mean log-probability differences are below 0.1 nats/token. No word-level deletion, blacklist, repetition penalty or additional model weights are involved. A rejected replacement retains the earlier supported draft; an empty new utterance stays empty. The browser always enables verification and speech detection. The WebSocket booleans remain available to explicit developer evaluation scripts; they are not exposed as UI options.

Whole-phrase support can hide unsupported copies of correctly recognized words. `backend/repetition.py` locates adjacent repetitions of 3–32-word units, ignoring case and punctuation. Single/two-word periodic units are excluded. Fast-tokenizer offsets are used only after exact re-encoding equality with the original generated IDs; ambiguous/shared token boundaries are skipped rather than guessed. Each copy uses its most favorable frozen-control mean lift. An extra copy fails only when its lift is below both 0.2 nats/token and 10% of the first copy's lift. This relative check preserved a subtle repeated-video control that an absolute 0.2 threshold rejected. An unsupported repeat authorizes checking at most three distinct existing beam alternatives, in score order, with both verification rules. Whole-phrase rejection alone does not trigger retries. Frozen visual prefixes are reused for all alternatives. Replacement IDs are transient and removed before the model result is returned.

The repetition rule used all four saved speech clips and constructed text/video repetition controls for development. It rejected eight extra-copy cases and admitted four truly repeated-video controls; these are artificial joins and generated captions, not reference-labeled natural repeated speech. The rule may still reject legitimate repeats or miss loops, especially nonadjacent, varied, short or unalignable repeats. `scripts/evaluate_repetition.py` reproduces these numeric checks. Logs record only copy counts and support scores, allowing a later live failure to be traced to generation versus display assembly without storing captions.

Teacher-forced BF16 scoring is not bitwise identical to autoregressive search. The first experiment checked exact equality of reconstructed versus captured prefixes, and measured small search/rescore mean differences (about 0.0003–0.0091) while quiet/speech evidence differences were much larger. The offline script tests shuffled controls too, but production uses frozen controls only. Original token IDs and video-derived tensors stay transient. Logs and reports contain numeric diagnostics, not captions.

The trial policy was recorded in ignored `models/visual_speech/grounding-trial-policy.json` using first-take results only. The second-take experiment then checked quiet/normal/subtle clips at three prefix lengths. These are small personal development experiments, not evidence of unchanged WER or reliable detection of every post-speech hallucination. Controls are artificial and may alter features beyond speaking motion. Common correctly spoken words may have little visual lift, and an unsupported suffix may escape a whole-phrase average. A larger generic decoder cannot replace the trained Qwen2.5-7B adapter/LoRA combination without compatible training; see the [FLARE decoder training description](https://arxiv.org/html/2610.19559v1#A1.SS2).

## Compatibility changes

`setup_model.py` creates `vendor/flare_runtime` from the pinned original without changing `vendor/FLARE`:

- Imports only inference models; avoids dataset/task setup and researcher-local audio/tokenizer paths.
- Uses deterministic package imports instead of the upstream `len(sys.argv)` debug switch.
- Supplies the local Qwen path with remote custom code disabled.
- Recovers the actual Whisper statistics buffer from the visual checkpoint, avoiding the unavailable original training `.npy` path.
- Loads the pretrained visual model, then the finetuned visual encoder, then all published adapter/LoRA parameters, checking coverage.
- Compiles only the authors' `beam_search` and `search` functions from their decoder CLI. Fixes its inconsistent three-value return when no EOS is generated to the four-value shape its caller requires.

`FLARE_MODEL_DIR` can point to another directory with the same layout. Missing models, unsupported environments and insufficient GPU memory are surfaced in `/api/status` and the UI. There are no mocked transcripts or speech-recognition fallbacks.

## Accuracy-preserving latency optimizations

The optimizations retain the same weights, BF16 arithmetic, beam 30, temperature 1.2, 25 fps sampling, and image transforms. The original benchmark below used 2-second partial updates and independent 6-second clips. The current continuous mode changes the video windows as described below. Its two visual input tensors remain `[1, 1, T, 88, 88]`; `T` varies. With ideal timestamps, the initial 2/3/4/5/6-second windows contain 51/76/101/126/151 frames; subsequent full windows contain 151. The released configuration keeps the visual encoder's temporal resolution rather than downsampling it.

Each WebSocket session shares immutable decoded JPEG frames, SFD boxes and raw landmarks between activity inspection and recognition. The two consumers keep separate sample timestamps and speech-decision state. Activity inspection stops before constructing unused FLARE ROIs. Interpolation and 12-frame smoothing still run with the complete current context. An aligned ROI is reused only when its source frame, exact transform bytes, mouth center, and normalization settings match. Up to four exact ROI variants per source frame avoid cache thrashing when timestamp resampling uses the same camera image at multiple positions. Speaking-detector crops likewise use exact source/padding/crop keys, while temporal scores are recomputed. Caches are bounded, evict old entries, and clear at session teardown; images remain in memory only.

The second optimization pass prepares incoming JPEGs, immutable face observations and brightness between scheduled updates. A streaming nearest-neighbor selector offers only the source frames chosen by the same 25 fps session grid. It does not alter inference sampling or skip frames required by a window. The same session worker gives inference priority over the bounded 64-frame preparation queue; a ready update waits behind at most one preparation call. Preparation and GPU inference never run concurrently. Unprepared/evicted frames use the ordinary path, and speculative quality failures are handled at the normal window boundary. This shifts work into capture time; it does not make all of that computation disappear. Speech scores, temporal state and transcript decisions still run only on scheduled windows.

Four CPU workers perform independent image warps using the same `skimage` function, transform, dtype and conversion order. At most 16 jobs are outstanding. Alignment fitting, smoothing and cache mutations remain on the calling thread, and results retain input-frame order. Light-ASD cropping constructs only the rectangle needed from its padded image, including the same constant-valued border, instead of allocating a complete padded camera frame.

The decoder reduces host/device transfers and redundant integer-index gathers. Floating-point operations, tensor shapes, beam ordering, score normalization, and stopping rules are unchanged. `backend.decoding.build_search(..., optimized=False)` retains the reference path for comparisons. Last-position-only vocabulary projection, alternate warp kernels, quantization, smaller beams, shorter clips, and cross-update visual feature/KV reuse were excluded because they could change numerical results, context, or search decisions.

The installed face-alignment package enables cuDNN autotuning. PyTorch's [cuDNN execution-plan caches are thread-local](https://github.com/pytorch/pytorch/blob/v2.9.1/aten/src/ATen/native/cudnn/Conv_v8.cpp#L330). A baseline-only repeatability control found identical complete beams/scores across 16 same-thread runs, but different beam alternatives/scores in 8 of 16 cross-thread runs with identical input pixels; all displayed words matched in that control. The paired fixed-window benchmark therefore runs both versions on one common worker to isolate code differences, without relaxing equality checks. Real WebSocket scheduling is evaluated separately. This is not a claim of bitwise deterministic live inference or unchanged WER on unseen speech.

A dedicated live inference thread plus broader warmup was tried and excluded after one comparison changed both model-input pixels and the transcript. A combined KV-copy kernel path was also evaluated without changing production search: exact-copy microbenchmarks were essentially tied at 50 positions (0.228 vs 0.223 ms) and slower at 150/400 positions (0.717/1.888 vs 0.323/0.908 ms), so it was excluded. The shipped decoder and existing warmup policy remain unchanged.

Activity and recognition preprocessing are also reported as subcomponents of preprocessing. Upload means CPU-to-GPU transfer. The browser's **Update timing** panel measures newest-frame capture to the next paint opportunity after transcript commit, plus JPEG encoding and a WebSocket round-trip probe. It retains at most 120 numeric samples and can download them without images or captions. Camera sensor exposure and word-aligned speech latency are not measured.

## Provisional utterances and final refinement

Production uses `UtteranceReader` in `backend/utterance_stream.py`. The six-second rolling buffer schedules activity checks; a separate bounded `VideoHistory` retains original timestamped JPEG frames for up to 80 seconds / 3,202 frames / 1,639,424,000 bytes. `backend/limits.py` defines the shared bounds. The additional history gives an in-flight decode time to complete while capture continues. Skipped activity intervals are recovered from history on the same 25 fps sampling grid. The first coalesced check includes the session origin. Loss of needed history ends the session explicitly, retaining the draft.

`FlareModel.inspect_activity` runs the unchanged speech classifier without FLARE decoding. An admitted interval opens an utterance with up to 1.6 seconds of preceding context. Every live decode receives the whole current utterance, and `UtteranceTranscript.revise` replaces its entire draft. Completed utterances alone form stable history. The previous fuzzy-merging code remains for legacy tests/comparison and is not the deployed production transcript path.

After at least 800 ms of confidently quiet evidence beyond the last active evidence time, the reader refines the retained utterance once, including 500 ms of ending context where available. This final pass bypasses the classifier only because speech already opened that utterance; a wholly quiet session can never invoke it. Stop similarly finalizes an active utterance once. If source frames, sampling phase, bounds and verification policy exactly match the preceding recognition, its owned result is reused instead of repeating identical GPU work. Further quiet updates preserve the committed result and do not decode it again.

The activity response now includes ordered confirmed speech regions (`speech_regions_version=1`). These retain each original onset, confirmation time, last active evidence and observed quiet closure. A coalesced update containing confirmed A, a full pause and unconfirmed movement B therefore finalizes A without extending it through B. A genuinely confirmed B is processed separately with its own retained context; multiple completed regions can be refined in the same update. Duplicate observations do not replay closures, and invalid/gapped observations do not supply silence evidence.

If tracking is interrupted and only quiet evidence returns, the unknown interval is not assigned a fabricated speech endpoint. The existing draft is kept with an interruption message instead of running a final decode over a falsely shortened clip. Fresh active evidence can recover the original retained utterance before finalization. Recognition of speech during a tracking interruption is not guaranteed.

Recognition uses at most 500 ms of ending context after an observed trailing quiet interval, including Stop. When active evidence reaches the latest mature classifier sample, the full camera endpoint is retained: the classifier has 480 ms of right context plus a possible fractional sample remainder, so blindly imposing a 500 ms cap could otherwise remove a valid final sampled frame. This fixes inconsistent quiet-tail handling without moving detector thresholds or substituting raw scores for smoothed evidence. Numeric `decoded_intervals` diagnostics expose the actual recognition bounds without recording captions or video.

The classifier's active timestamps mark smoothed speaking evidence, not word boundaries. Missing/uncertain observations do not create a pause. Final predictions can correct initial words or remove an incorrect whole draft. They are not guaranteed more accurate: actual reference transcripts are needed to measure word error rate.

Utterances default to 30 seconds and can be set to 60 seconds before a session, including context (751 or 1,501 samples on ideal inclusive 25 fps timestamps). The WebSocket `start.max_utterance_seconds` accepts integer 30 or 60 and rejects other values, including booleans. `/api/status` advertises both options, the default, and the maximum; the start acknowledgement reports the selected limit. The UI persists the choice and disables it during capture. A pause resets the utterance interval; total session duration is not limited to one utterance. Longer uninterrupted phrases still stop explicitly, retaining the draft. There is no arbitrary mid-word split or silent short-tail discard.

The shared JPEG-decode and preprocessing caches retain up to 2,001 unique frames, preventing the old 400/500-frame caches from thrashing on longer utterances and avoiding duplicate pixels between activity and recognition. Preprocessing admits up to 80 seconds for coalesced gate recovery. Frame rate, smoothing, crops, normalization, weights, beam search, and visual/repetition verification remain unchanged. Larger caches can use more host memory; they release all retained arrays when the session ends.

`scripts/check_long_utterance.py` joined existing consented speech recordings and verified complete inputs at 12, 20, 30, 45 and 60 seconds. GPU decoding took approximately 0.96, 1.10, 1.34, 1.61 and 23.09 seconds respectively; the last case peaked at 24.74 GiB allocated in the model process. Verification took 0.17–0.93 seconds in these five cases. Preprocessing was measured separately and benefited from prior growing-window cache entries. The large 60-second latency motivates a 30-second default, with explicit slower 60-second mode. These artificial joins have no reference transcription and do not establish recognition accuracy on naturally long speech. The live mode sends a full minute through the normal WebSocket, bypassing only speech segmentation to force one utterance while retaining both recognition checks.

The frontend distinguishes provisional utterance text from committed text, displays refinement status, collects 640 ms of Stop context, and waits for an in-flight JPEG before sending Stop. Encoding failure or a two-second encoding timeout ends the session explicitly. Cached frame/landmark reuse, full FLARE weights, BF16, beam 30 and temperature 1.2 remain in place. Longer inputs and one additional final pass may increase latency; previous fixed-window speed measurements do not measure this mode.

Tests cover whole-prefix corrections, repeated quiet updates, independent utterances, Stop finalization, coalesced history, full-minute inputs, the default 30-second boundary, selected-limit validation, explicit overlength errors, and the production WebSocket branch. `scripts/check_speaking_gate.py --live --mixed` checks the real model on saved development clips and requires exactly one final refinement per speaking clip, none for quiet clips. It does not save recognized words or establish word accuracy.

Early preview has its own gate and recognition state, sharing only cached image observations and exact crop results. It runs only before a trusted utterance opens, using at most the latest two seconds of available video and never crossing a committed endpoint. It remains eligible after long silence. It can attempt at most every 500 ms, and only when at least 550 ms remains before the scheduled update (including a 50 ms safety margin). Existing recognition and incoming-frame preparation have priority. A deadline and cancellation checks between decoder/visual passes abandon previews when regular work or Stop arrives; an individual GPU pass is not preemptible. Quiet, invalid, late or failed previews return no words. Every generated preview still uses beam 30, temperature 1.2, the full visual-evidence and repetition checks, and the ordinary input transforms.

A separately copied Qwen decoder has its trained LoRA adapters merged for early previews only. The original decoder's module registry and weights stay separate; trusted drafts and final recognition use the original model. BF16 merging changes rounding and can change predictions, so it is intentionally excluded from the trusted path. The visual encoder is shared and serialized under the model lock. Short synthetic 31/32-frame warmups populate no session caches. The merged copy requires roughly 15 GB of additional GPU memory; it is skipped when fewer than 28 GiB are free after loading the main model, preserving headroom for long utterances. Preview then uses the original decoder with the same budget.

Preview messages never enter `UtteranceTranscript`, recognized fallback history, copy/download text, or word counts. Their separate dashed display expires after one second and clears on a trusted response, Stop or disconnect. Camera timestamps reject stale responses. Earlier words are less reliable and may disappear; missing an early preview never prevents the normal speech detector from recognizing the utterance.

The first unmerged preview trial exceeded its available decode budget on normal speech. One of the three cross-process final-transcript comparisons also differed; the existing thread-local cuDNN plan variability described above means that live inference is not bitwise reproducible. The final merged-preview off/on comparison used the same isolated runtime. Normal speech first appeared in the early box at 1919 ms, versus 2580 ms for the first trusted caption with preview off; trusted recognition with preview on arrived at 2445 ms. Subtle speech did not pass the early gate and gained no early text (first trusted responses 2514 vs 2585 ms). All three final transcripts matched, and quiet head motion and the joined post-speech quiet interval produced no nonempty early previews. This is a small local development check, not reference-transcript WER or a guarantee for other speech. Timings exclude laptop encoding, tailnet transport and display paint. Reports are local numeric/equality-only JSON under `models/visual_speech/round3-*`; camera images, recognized captions and token IDs are not saved by these experiments.

A repeated merge benchmark used three timed runs per version after warmup, alternating order on identical input tensors. Across six speech windows, mean decoding (including the visual encoder) fell from 359.4 to 303.0 ms, about 16%. Winning tokens matched in all six speech windows in this repeat, and all 12 verification decisions matched. An earlier pass changed two of six speech-window winners, and the merged beam scores are not bitwise identical. The optimization therefore remains preview-only. Results: `models/visual_speech/round3-merge-warm.json` and the earlier `round3-merge.json`.

`benchmark_decoder_options.py` also tested one-token `torch.compile(dynamic=True, mode='reduce-overhead')`, exact-shape CUDA graphs, and draft reuse speculation. Compilation exceeded a six-minute limit before its first compiled beam-search warmup finished. Direct graphs preserved complete beams/scores in all 12 fixed windows, but warm speech decoding improved only 362 to 351 ms on average while first-use capture raised 374 ms to 1409 ms; graphs stay benchmark-only. Greedy speculative decoding using previous-window tokens as proposals averaged 66.4 to 69.5 ms across six speech windows (slower), accepting just one of 12 proposed draft tokens. It matched ordinary greedy output in those six speech cases but greedy matched beam-30 output in only one. ## Native camera detail (2026-11-04)

Live capture and the opt-in example recorder preserve up to 1280×960 pixels (normally native 1280×720), replacing the previous 640×480 cap. No upscaling is performed. SFD and FAN operate on that supplied image; the 100-pixel minimum landmark span remains unchanged, and small/lost faces produce camera guidance. The model still receives the same 25 fps, 88×88 dual-stream format with the same alignment, normalization, speech gate, grounding checks and decoder. Higher-resolution pixels can change predictions, so this is not an exact-output or WER guarantee.

On this GPU, a 24-frame resolution-cost check measured median face detection plus landmarks at 9.0 ms for 640×360 and 17.0 ms for 1280×720. Four live 8-second replays (two per resolution) measured median recognition-update processing at 492.5 ms and 557.0 ms, respectively, with maximum measured inference queue delay 0.2 ms. All four produced a final caption. Reports: `models/visual_speech/distance-resolution-cost.json` and `distance-live-cost.json`. The 720p test inputs were resized legacy examples, useful for cost/integration only; actual distant-speaker accuracy requires native camera testing. Upload volume in that replay rose from 7.43 to 16.81 MB per clip.

### Detection-scale correction

After the native-resolution rollout, the user reported no captions and the message “Keep only one person in the camera view.” Session metrics confirmed capture checks were withholding recognition; the actual new scene was not saved. SFD now operates on the previous 640×480-bounded view, with box coordinates mapped independently along each axis back to the original frame. FAN, FLARE crops and Light-ASD crops still use native pixels. This addresses the suspected scale-dependent extra detections without weakening the multi-face guard or speech thresholds. Empty detections do not trigger a full-resolution retry. Legacy low-resolution input keeps its original detection path. Capture failures now include a categorical issue code in the numeric diagnostic metrics.
